\section{Research attempt: Versioned attempts and a grading join that changes the result}
Consider two worksheet revisions with the same local exercise identifier $q$. Revision $v_1$ asks for $1+1$ and accepts response 2; revision $v_2$ asks for $1+2$ and accepts response 3. A learner response record storing only $(q,2)$ cannot determine the correct grade: it is correct for the first revision and incorrect for the second. Joining that record to whichever reusable source is currently latest can retroactively change the grade without any change to the learner's response.

In a finite relational model, separate immutable source revisions, delivery instances, learner attempts, and evaluations. An attempt contains a delivery identifier; each delivery points to exactly one source revision; an evaluation points to exactly one attempt and one scoring-rule revision. If every such pointer has a unique target, following the pointer chain determines a unique source and scoring rule for an evaluation. This follows by composition of functions: a unique next target at each of the finitely many stages gives exactly one complete chain. A missing pointer instead gives an explicit unresolved association, not a valid grade.

These roles also prevent a mistaken reuse operation. Copying reusable source should not automatically copy an old learner's name and response into a new learner's attempt. In the model, source is a projection that omits attempt fields, so changing any learner response leaves that projection unchanged. Conversely a projection that includes a learner name fails this independence test immediately when two attempts of the same source have different learners. This proves a simple noninterference property of the selected data separation; it is not a privacy certification for real storage or publication.
