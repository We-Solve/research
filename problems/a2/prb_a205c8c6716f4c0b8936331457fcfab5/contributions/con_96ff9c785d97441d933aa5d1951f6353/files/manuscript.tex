\section{Research attempt: A stable course link can expose inconsistent slide versions}
Suppose a course index points to slide decks $A$ and $B$, and deck $A$ links to a particular slide in $B$. Publishing a new index and new $A$ while leaving old $B$ in place can give a reader a mixture in which the referenced slide is absent or has changed meaning. A single stable course URL does not prevent this mixed-version state.

In an abstract snapshot model, a course manifest $M$ records an ordered list of deck-version identities and their internal target maps. Each listed deck version is immutable and already available. Validate every cross-deck reference against the exact listed version of its destination. Publish by atomically changing the stable course pointer to $M$, and have readers retain that manifest identity throughout their session. Then every deck fetched and every cross-deck reference followed agrees with one validated manifest. Proof: the initial pointer chooses one $M$; each fetch uses its recorded version; every validated edge points to a recorded target in that version. Induction on followed references keeps the session inside the chosen snapshot.

Decks in one manifest need not share the same version number: a course can deliberately combine $A_5$ and $B_2$. Consistency means agreement with the chosen manifest, not numerical equality of version labels. Conversely, if a deck link bypasses the manifest through an unversioned latest URL, the induction fails at that edge. Keeping the old manifest but deleting a referenced immutable deck also violates the availability premise.

The model solves a limited identity-consistency problem under atomic publication and retention assumptions. It does not implement collection search, slide embedding in a book, authoring workflows, or the desired update cadence, all of which remain part of the broad original request.
