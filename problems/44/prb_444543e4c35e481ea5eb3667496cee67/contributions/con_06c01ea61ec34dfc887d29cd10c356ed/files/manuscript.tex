\section{Research attempt: A selected fragment cannot reveal omitted definitions}
Let two source documents have exactly the same selected text, a macro reference $R$, but different surrounding definitions: one defines $R$ as the real-number symbol and the other as the rational-number symbol. The intended selected meanings differ. Any deterministic converter receiving only the selected characters must produce the same output for both inputs, so it cannot preserve both meanings. A probabilistic converter likewise has the same output distribution on the identical input; it cannot have success probability one for two distinct required outputs. Thus an AI implementation does not remove the missing-information obstruction.

For a declared finite acyclic macro language, a contextual converter can instead receive the selected syntax tree together with definitions reachable from its references. Topological expansion gives a fully expanded tree: base definitions contain only literals; inductively each later definition substitutes already determined trees. This terminates by acyclicity and is independent of unused definitions. A translation that preserves the meaning of each constructor then preserves the selected meaning by structural induction on the expanded tree. These are conditional correctness facts, not an implemented converter.

Selection boundaries introduce a separate issue. In the expression tree representing $(a+b)c$, a character selection beginning at $b$ and ending after the closing parenthesis is not itself a complete expression node. A tool that assumes every highlighted range is a standalone parse tree has no such node to translate. It must either enlarge the selection under an explicit policy or return a boundary diagnostic. Quietly guessing a wrapper can alter meaning in the surrounding document. The analysis identifies two missing inputs: semantic environment and structural selection boundaries.
