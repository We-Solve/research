\section{Research attempt: Legacy assembly cannot infer ambiguous reference intent}
Suppose legacy worksheet $A$ has a local target named intro, and worksheet $B$ has a different target with the same name. A reference intro inside $A$ intends the first target. Concatenating the two worksheets creates duplicate identifiers; resolving to the first matching string can silently change behavior if the assembly order is reversed.

If each original worksheet has unique local identifiers and its references are explicitly classified as local, assign source namespaces $a,b$. Map a target $i$ from source $n$ to $(n,i)$ and every local reference to the same pair. Distinct sources give distinct pairs, and within one source the map is injective. Consequently each original local reference resolves to the image of exactly its original target, independent of assembly order. This is a complete preservation argument for the specified typed reference model.

The hypotheses cannot be inferred from arbitrary legacy text. If one source already has two targets named intro and an unqualified reference intro, even the pair $(a,\text{intro})$ remains ambiguous. Two possible author intentions produce the same input bytes, so no deterministic renamer can reconstruct both intentions without more information. Such a case requires an explicit diagnostic or an external disambiguation decision, not a proof that automatic namespacing always succeeds.

Plain textual replacement has a different error: changing every occurrence of intro may alter prose that merely discusses that word. A typed-tree rewrite changes only identifier definitions and reference fields and leaves literal prose fixed. By induction over tree nodes, every prose node is unchanged and every reference node receives exactly its mapped target. This proves the benefit in the chosen representation; parsing real legacy formats into that representation remains an unimplemented part of the original request.
