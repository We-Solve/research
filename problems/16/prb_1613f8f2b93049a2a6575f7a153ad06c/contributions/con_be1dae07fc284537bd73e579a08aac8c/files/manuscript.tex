\section{Research attempt: Why a search for TODO cannot certify Guide completeness}
The source contains a historical observation about unfinished Guide sections. No current inventory follows from it. A literal-string scanner for TODO has both kinds of error under a minimal document model. A completed documentation paragraph explaining that the word TODO marks unfinished work contains the string but is not unfinished. An empty required section titled ``Installation'' may contain no such string while still lacking its required instructions. Therefore neither presence nor absence of the token characterizes completion.

Specify instead a finite versioned set of required sections $R$ and a predicate $P_r$ for what counts as evidence of completion for each section $r$. An audit result can enumerate the set $U=\{r\in R:P_r\text{ fails or is unverified}\}$. If each predicate is a decidable finite check on the chosen snapshot, enumeration terminates and its reported set is exact for those predicates: each required section is visited once and included exactly according to its check. It still does not prove that the predicates capture every educational requirement.

As a concrete finite test, let $R=\{a,b\}$, require each section to contain a command and an expected output, and let $a$ contain explanatory prose with TODO but both required fields, while $b$ contains a command only. The token scanner flags $a$ and misses $b$; the declared structural check passes $a$ and flags $b$. If the requirement changes to include troubleshooting, the previous passing result for $a$ is no longer a completeness certificate. Both the source snapshot and the requirement revision must therefore be part of an audit claim. No such real Guide-wide audit was executed here.
