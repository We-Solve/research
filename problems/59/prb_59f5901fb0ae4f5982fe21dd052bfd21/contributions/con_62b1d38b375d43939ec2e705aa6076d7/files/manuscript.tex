\subsection{Postprocessing helps utility only relative to a model}
We test a precise way to improve a release without spending further privacy. Suppose $M$ obeys $(\varepsilon,\delta)$-differential privacy, meaning $P_D(A)\le e^\varepsilon P_{D'}(A)+\delta$ for adjacent databases and measurable output events. Let $K$ be a randomized output transformation whose conditional distribution depends only on the released value, not again on the private database.
\begin{proposition}
The transformed mechanism obeys the same privacy inequality. For a true empirical mean $\mu\in[0,1]$, clipping a Laplace release $Y=\mu+Z$ to $[0,1]$ weakly decreases squared error on every outcome. With $Z$ of scale $b=1/(n\varepsilon)$, $n\ge1$, $\varepsilon>0$, the clipped mean-square error is at most $2b^2$.
\end{proposition}
\begin{proof}
For any transformed-output event $B$, set $f(y)=K(y,B)\in[0,1]$. The layer-cake identity $f(y)=\int_0^1\mathbf1_{\{f(y)>t\}}dt$, followed by integration of the privacy inequality for these level sets, gives
\[
\int f\,dP_D\le e^\varepsilon\int f\,dP_{D'}+\delta.
\]
This is exactly privacy of the transformed release. If $Y<0$, clipping moves it to 0, which is no farther from any $\mu\in[0,1]$; if $Y>1$, the analogous statement holds at 1; in the interval the value is unchanged. Thus the squared-error comparison is pointwise. Finally,
\[
\mathbb E Z^2=b^{-1}\int_0^\infty z^2e^{-z/b}\,dz
=b^2\int_0^\infty t^2e^{-t}\,dt=2b^2,
\]
where two integrations by parts evaluate the last integral. A one-row change changes the empirical mean by at most $1/n$, and the Laplace density ratio is at most $\exp((1/n)/b)=e^\varepsilon$, giving the stated private starting release.
\end{proof}
The attempted inference ``privacy itself ensures statistical usefulness'' fails even for this setting: the constant release 0 is 0-private but has squared error 1 on a database of all ones. Clipping uses the known parameter interval and a particular loss; it is not a universal utility theorem. A transformation that reopens the database is not covered by the kernel argument.
